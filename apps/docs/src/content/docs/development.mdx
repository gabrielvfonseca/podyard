## Monorepo tooling

Podyard uses **Bun workspaces** + **Turborepo** + **TypeScript project references**. Shared code lives in `packages/` and is imported as `@podyard/<name>`.

## Common scripts

Run from the repo root:

| Command | What it does |
| --- | --- |
| `bun dev` | Start all apps in parallel (web 3001, api 3002, docs 3004) |
| `bun run build` | Build every package and app |
| `bun run typecheck` | Type-check every package and app |
| `bun run lint` | Lint the whole repo |
| `bun test` | Run all Vitest suites |

Per-app scripts are in each `apps/*/package.json` and `packages/*/package.json`.

## API development

The API is a standalone Hono server:

```bash
cd apps/api
bun --bun src/index.ts
```

- Routes are defined in `src/routes/` and mounted in `src/app.ts`.
- Better Auth is mounted at `/api/auth/*` via `auth.handler(c.req.raw)`.
- The server binds port **3002** by default.

## Database

Schema lives in `packages/database/src/schema.ts`.

```bash
cd packages/database
bun run db:generate   # generate a SQL migration from the schema
bun run db:push       # push schema to database
bun run db:migrate    # apply migrations
bun run db:studio     # open Drizzle Studio
```

## Testing

Each package/app uses Vitest. Run a single suite:

```bash
cd apps/api
bun test
```

## Environment variables

All env validation uses [`@t3-oss/env-core`](https://t3.gg). Rules:

- Every variable has a zod schema and an error message.
- **Empty strings are rejected** — omit a variable instead of leaving it empty.
- Client-safe variables are prefixed `NEXT_PUBLIC_` (see the `clientPrefix` option in each `env.ts`).
